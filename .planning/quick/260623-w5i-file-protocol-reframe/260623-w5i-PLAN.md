# Quick Task 260623-w5i: Reframe the EP-133 file-transfer protocol

Foundational fix. The app's entire SysEx file layer is mis-framed, so EVERY file operation
fails on real hardware: active-group sync, sample import (`putSampleFile`), and project
browsing (`listProjects`). Confirmed on a physical EP-133 K.O. II (sw 2.0.5) via macOS
`sendmidi`/`receivemidi`. Full findings in memory `ep133-sounds-upload-protocol.md` and
`.planning/phases/05-splice-sample-sync/05-OPEN-QUESTIONS-RESEARCH.md`.

## Hardware-verified ground truth (this is the contract)

Frame envelope (unchanged, proven by working greet):
`F0  00 20 76  <deviceId>  40  <flags>  <reqId7>  <command>  <7bit-packed payload>  F7`
- flags = `BIT_IS_REQUEST(0x40) | BIT_REQUEST_ID_AVAILABLE(0x20) | (reqId>>7 & 0x0F)`.
- Device **deviceId = 0x33** (read it from the greet RESPONSE frame[4]; do not hardcode).

**Bug 1 — wrong command byte.** File ops currently use `command = CMD_PRODUCT_SPECIFIC (127)`
with payload `[TE_SYSEX_FILE(5), subcmd, …]`. The device rejects this with a generic 1-byte
status `0x01`. CORRECT: `command = TE_SYSEX_FILE (5)`, and the payload starts at the
**subcommand** (NO leading `5` byte). Verified: command=5 + `[FILE_LIST(4), page u16, node u16]`
produced a real file-subsystem response.

**Bug 2 — missing FILE_INIT.** Even with command=5, an un-initialized session returns the
ASCII error `"can't list unless initialized"`. The device requires a one-time
**`FILE_INIT` (subcmd `TE_SYSEX_FILE_INIT = 1`)** handshake per connection first:
- Request: command=5, payload `[INIT(1), flags, maxResponseLength u32 BE]`.
  (Reference `SysExFileInitRequest(maxResponseLength, flags).asBytes()` = `[1, flags, u32]`.)
- Response carries the negotiated chunkSize. flags: try `TE_SYSEX_FILE_INIT_SUBSCRIBE = 1`.
- Verified working sequence on hardware: `INIT(cmd5)` → `LIST node 0 (cmd5)` returned the root
  directory containing `sounds` and `projects` with node IDs.

**Bug 3 — dispatcher.** Responses now arrive under `command = TE_SYSEX_FILE (5)`, NOT 127, and
the response payload does NOT repeat the subcommand (it begins with op-specific data — e.g.
LIST → `[page u16, …entries]`, INIT → `[status/chunkSize…]`). Correlate response→request by the
echoed **requestId** (frame[7], plus high bits from frame[6]&0x0F), and/or by the single
in-flight file op (file ops are already serialized via `statsQueryInFlight`/`transferInFlight`).
The current `command==127 && payload[0]==TE_SYSEX_FILE` routing is wrong on both checks.

## Task 1 — Reframe all file builders to command=TE_SYSEX_FILE

**File:** `AndroidApp/.../domain/midi/SysExProtocol.kt`

- Add `buildFileFrame(deviceId, requestId, body: ByteArray)` = `buildFrame(deviceId, command = TE_SYSEX_FILE, requestId, body)` where `body` begins with the file subcommand.
- Reroute every file builder through it, dropping the leading `TE_SYSEX_FILE` byte from each payload:
  - `buildFileSystemFrame` (path ops: LIST/GET/PUT/METADATA by path) → body `[subcmd, pathBytes…, extra…]`.
  - `buildFileListByNodeFrame` → body `[FILE_LIST(4), page u16, nodeId u16]`.
  - `buildFilePutInitFrame`, `buildFileCreatePutInitFrame`, `buildFilePutDataFrame`, `buildFileGetInitFrame`, `buildFileGetDataFrame`, `buildFileMetadataFrame` → same treatment (subcmd first, no leading 5).
- Do NOT change the 7-bit packing yet (see Task 4) or the envelope/flags.
- Keep `CMD_PRODUCT_SPECIFIC` constant (greet/other uses) but it must no longer wrap file ops.

## Task 2 — Adopt the device ID from greet

**File:** `AndroidApp/.../domain/midi/MIDIRepository.kt`

- In `dispatchSysEx`, the `CMD_GREET` branch: set `currentDeviceId = message[4].toInt() and 0x7F` (the device's real id, 0x33) before/after completing `pendingGreetDeferred`. All later frames use it.
- Ensure a greet happens on connect before any file op (queryDeviceStats already greets — confirm ordering).

## Task 3 — FILE_INIT handshake

**Files:** `SysExProtocol.kt` + `MIDIRepository.kt`

- `SysExProtocol`: add `TE_SYSEX_FILE_INIT = 1` (and `TE_SYSEX_FILE_INIT_SUBSCRIBE = 1`); add `buildFileInitFrame(deviceId, requestId, maxResponseLength: Int, flags: Int = TE_SYSEX_FILE_INIT_SUBSCRIBE)` → body `[INIT(1), flags, maxResp u32 BE]`. Add a `parseFileInitResponse(body): chunkSize` (verify exact offset on hardware; reference reads `a[1..4]` as u32 — confirm against the captured INIT reply).
- `MIDIRepository`: add `private var fileSessionInitialized = false` and `private var deviceChunkSize: Int`. Add `suspend fun ensureFileSessionInit()` that, once per connection, sends FILE_INIT, parses chunkSize, sets the flags. Call it at the top of `resolveNodeId`, `listProjects`, `putSampleFile`, `getActiveGroupIndex`, etc. (or once on connect). Pick a safe `maxResponseLength` (e.g. 512) and refine from the negotiated chunkSize. Reset `fileSessionInitialized=false` on disconnect.

## Task 4 — Dispatcher: route command=5 + correlate by requestId

**File:** `MIDIRepository.kt` `dispatchSysEx` / `dispatchFileResponse`

- Add a `command == TE_SYSEX_FILE (5)` branch. Pass the UNPACKED payload (op-specific; no leading subcmd) to a correlation step.
- Correlate to the in-flight request: read reqId = `(message[6].toInt() and 0x0F shl 7) or (message[7].toInt() and 0x7F)`. Maintain a small map reqId→pending-op, OR (simpler, given serialization) dispatch to whichever single file deferred is currently active (`pendingNodeListDeferred` / `pendingPutAckDeferred` / `pendingMetadataJsonDeferred` / `pendingGetInitDeferred` / new `pendingFileInitDeferred`).
- Remove the obsolete `command==127 && payload[0]==TE_SYSEX_FILE` path.
- **Hardware-verify each op's response shape** (LIST, INIT, METADATA GET, PUT ack, GET) since the response no longer echoes the subcommand — adjust parsers (`parseFileListEntries`, metadata, PUT status) to the real offsets.

## Task 5 — 7-bit packing convention check

- Confirm `pack7bit`/`unpack7bit` match the device. ASCII fields decoded correctly in captures, but a hand-decode of binary fields (node IDs, sizes, chunkSize) was misaligned — verify the high-bits placement/order against a known device response (e.g. the greet payload `product:EP-133;…` and a LIST reply) during implementation. Fix the convention if it diverges; add a unit test round-tripping a captured device frame.
