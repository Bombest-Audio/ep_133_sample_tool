# Quick Task 260621-lg4: Correct the /sounds upload protocol + decode robustness

Implements the verified findings in `.planning/phases/05-splice-sample-sync/05-OPEN-QUESTIONS-RESEARCH.md`
(reverse-engineered from the device's own reference tool `data/index.js`). The currently shipped
path-string `putSampleFile` does NOT match the device protocol — rework it. Plus fix a real
MediaCodec decode bug and add the device's input guards.

## Ground-truth constants (from data/index.js — already extracted, use as-is)

- `TE_SYSEX_FILE = 5`, `TE_SYSEX_FILE_PUT = 2`, `TE_SYSEX_FILE_PUT_TYPE_INIT = 0`, `TE_SYSEX_FILE_PUT_TYPE_DATA = 1` (all already in SysExProtocol.kt).
- `TE_SYSEX_FILE_CAPABILITY_READ = 4`, `FILE_TYPE_FILE = 1`. INIT `flags = CAP_READ or FILE_TYPE_FILE = 5`.
- New-file `fileId = 0` (device assigns the real one). Filename sliced to ≤54 chars, NUL-terminated. Metadata optional (send null for now).
- Device native rate 46875 Hz, format s16. Limits: max 20.0 s, source rate 3000–768000 Hz.
- DATA frames carry only `[FILE_PUT, TYPE_DATA, page u16, chunk]` — NO fileId. So the upload does not need to parse the INIT response; mirror putProjectArchive's fire-INIT → page-DATA → await STATUS_OK.

## Task 1 — SysExProtocol: add the correct create-file PUT INIT builder

**File:** `AndroidApp/app/src/main/java/com/ep133/sampletool/domain/midi/SysExProtocol.kt`

Add constants (near the other TE_SYSEX_* consts): `TE_SYSEX_FILE_CAPABILITY_READ = 4`, `TE_SYSEX_FILE_TYPE_FILE = 1`.

Add a new builder + payload mirroring the reference `SysExFilePutInitRequest.asBytes()` (with the project's leading `TE_SYSEX_FILE` subsystem byte, exactly like the existing `buildFilePutInitPayload`):

```kotlin
/**
 * Build a FILE_PUT INIT for CREATING a new file under [parentNodeId] (e.g. the /sounds dir).
 * Matches the device reference tool (data/index.js SysExFilePutInitRequest): announces the
 * parent dir, a fileId of 0 (device assigns the real id), the byte size, and the filename.
 * Metadata is optional and omitted when null.
 */
fun buildFileCreatePutInitFrame(
    deviceId: Int,
    parentNodeId: Int,
    fileSize: Int,
    filename: String,
    requestId: Int,
    flags: Int = TE_SYSEX_FILE_CAPABILITY_READ or TE_SYSEX_FILE_TYPE_FILE,
    fileId: Int = 0,
    metadataJson: String? = null,
): ByteArray {
    val nameBytes = filename.take(54).toByteArray(Charsets.US_ASCII)
    val payload = ArrayList<Byte>(16 + nameBytes.size)
    payload.add(TE_SYSEX_FILE.toByte())
    payload.add(TE_SYSEX_FILE_PUT.toByte())
    payload.add(TE_SYSEX_FILE_PUT_TYPE_INIT.toByte())
    payload.add(flags.toByte())
    payload.add((fileId shr 8).toByte()); payload.add((fileId and 0xFF).toByte())          // u16 BE
    payload.add((parentNodeId shr 8).toByte()); payload.add((parentNodeId and 0xFF).toByte()) // u16 BE
    payload.add((fileSize shr 24).toByte()); payload.add((fileSize shr 16).toByte())
    payload.add((fileSize shr 8).toByte()); payload.add((fileSize and 0xFF).toByte())       // u32 BE
    payload.addAll(nameBytes.toList()); payload.add(0)                                       // filename + NUL
    if (metadataJson != null) { payload.addAll(metadataJson.toByteArray(Charsets.US_ASCII).toList()); payload.add(0) }
    return buildFrame(deviceId, CMD_PRODUCT_SPECIFIC, requestId, payload.toByteArray())
}
```
(Match the surrounding code style — if the file favors `byteArrayOf`/explicit arrays over ArrayList, use that. The wire payload order is the contract: `[5,2,0,flags, fileId u16, parentId u16, fileSize u32, name…, 0x00, (meta…,0x00)?]`.)

Do NOT change the existing `buildFilePutInitFrame`/`buildFilePutInitPayload` (still used by putProjectArchive) or `buildFilePutDataFrame` (already correct for DATA + works for the zero-length terminator when passed an empty chunk).

## Task 4 — AudioDecoder: honor KEY_PCM_ENCODING (float/16-bit)

**File:** `AndroidApp/app/src/main/java/com/ep133/sampletool/domain/audio/AudioDecoder.kt`

MediaCodec PCM output is not guaranteed 16-bit (FLAC/HD → float). Fix:
1. Track the output PCM encoding. On `INFO_OUTPUT_FORMAT_CHANGED` (and once before the loop from the initial format), read it:
   ```kotlin
   val enc = if (fmt.containsKey(MediaFormat.KEY_PCM_ENCODING))
       fmt.getInteger(MediaFormat.KEY_PCM_ENCODING) else AudioFormat.ENCODING_PCM_16BIT
   ```
   Use `codec.outputFormat` on the format-changed event.
2. Extract a pure, JVM-testable top-level/companion function:
   ```kotlin
   fun pcmBytesToShorts(bytes: ByteArray, encoding: Int): ShortArray
   ```
   - `ENCODING_PCM_16BIT` → current LE Int16 path.
   - `ENCODING_PCM_FLOAT` → read LE Float32, `(f.coerceIn(-1f,1f) * 32767f).roundToInt().toShort()`.
   - `ENCODING_PCM_24BIT_PACKED` / `ENCODING_PCM_32BIT` → either downshift to 16-bit, or (minimum viable) throw `IOException("unsupported PCM encoding: $encoding")` so it surfaces as a per-row error rather than silent garbage. Pick downshift if simple; otherwise throw — document the choice.
3. Replace the final `bytesToShortArray(pcmBytes)` call with `pcmBytesToShorts(pcmBytes, encoding)`.
4. Optionally request 16-bit before configure: `format.setInteger(MediaFormat.KEY_PCM_ENCODING, AudioFormat.ENCODING_PCM_16BIT)` — but STILL handle float on output (it's a request, not a guarantee). Update the false "always 16-bit LE at API 29+" doc comment.

Add `import android.media.AudioFormat` and `kotlin.math.roundToInt` as needed.
