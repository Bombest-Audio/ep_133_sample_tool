# Phase 999.3 Plan 03: Firmware Update Banner + Custom Tab Handoff Summary

Wave 3 of the firmware update detection feature: wires the state machine from Plan 02 into visible UI and routes the "Open updater" tap to Chrome Custom Tab.

## What was built

**DeviceScreen.kt — `FirmwareUpdateBanner` composable**

Private composable that renders based on `FirmwareUpdateState`:
- `UpdateAvailable(current, latest)` — a panel-radius Row with an orange-tinted background (`t.accent.copy(alpha = 0.12f)`) and matching border. Text reads "Firmware ${state.latest} available" in bold mono. A `TextButton` labeled "Open updater" (orange accent color) calls `onOpenUpdater()`.
- `Checking` — a 14dp `CircularProgressIndicator` in teal (`t.live`) with a "CHECKING FIRMWARE…" label in the muted mono style. No user action needed.
- `Idle` / `UpToDate` / `Unknown` — `else` branch renders nothing (empty).

The banner is inserted in the `DeviceScreen` body between `StatsGrid` and `ChannelSelector`, with `firmwareUpdate` collected via `collectAsState()`.

`showSnackbar(message: String)` added to `DeviceViewModel` as a public wrapper over `_snackbarMessage.value`, so MainActivity can push a snackbar without touching the private flow directly.

**MainActivity.kt — `onOpenFirmwareUpdater` wired**

Immediately after the three existing SAF callback lines (`onRequestBackup`, `onRequestRestore`, `onRequestPick`), mirrors the same pattern:

```kotlin
deviceViewModel.onOpenFirmwareUpdater = {
    try {
        val customTabsIntent = CustomTabsIntent.Builder().build()
        customTabsIntent.launchUrl(this, Uri.parse("https://teenage.engineering/apps/update"))
    } catch (e: Exception) {
        deviceViewModel.showSnackbar("No browser available to open the updater")
    }
}
```

Import `androidx.browser.customtabs.CustomTabsIntent` added. `android.net.Uri` was already imported. No other changes to MainActivity.
