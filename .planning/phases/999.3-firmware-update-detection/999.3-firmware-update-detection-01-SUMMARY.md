# Phase 999.3 Plan 01: Firmware version model + TE downloads-page catalog Summary

Pure Kotlin `FirmwareVersion` value type with zero-pad comparison and `TeFirmwareCatalog` TE page scraper with date-exclusion filter, bundled 2.5 floor, and 21 passing JVM unit tests.

## What Was Built

**FirmwareVersion** — `data class FirmwareVersion(val parts: List<Int>) : Comparable<FirmwareVersion>`. The comparator zero-pads the shorter operand, making `2.5` ([2,5,0] padded) > `2.0.5` ([2,0,5]). `companion fun parse(raw: String?)` returns null on null/blank/non-numeric. No Android imports.

**TeFirmwareCatalog** — contains the `FirmwareCatalog` interface (`suspend fun latestVersion(): FirmwareVersion?`), the `LATEST_KNOWN_FIRMWARE = 2.5` constant, and three internal functions:
- `parseVersions(html)` — regex `\d+\.\d+(?:\.\d+)?`, parse each token, discard `parts[0] > 50` (rejects dates like `2026.06.24`), return max.
- `floorToBundled(scraped)` — returns `scraped` if newer than bundled, `LATEST_KNOWN_FIRMWARE` otherwise. Null input → bundled fallback (FW-02 offline guarantee).
- `TeFirmwareCatalog.latestVersion()` — `HttpURLConnection` on `Dispatchers.IO`, 5 s timeouts, `Log.w("EP133APP", ...)` on non-200 and on exception, calls `floorToBundled(parseVersions(body))`.

## Tests

**FirmwareVersionTest** (10 tests): parse valid 2-part and 3-part strings, parse null/empty/blank/non-numeric returns null, zero-padding comparison (`2.5 > 2.0.5`), 3-part ordering, equality after padding, full known TE history order descending.

**TeFirmwareCatalogParserTest** (11 tests): realistic fixture with `2026.06.24` date + multiple versions returns `2.5`; date-only fixture returns null; single version; empty string; `major=51` excluded; `major=50` not excluded (borderline); multiple versions returns max; date + older version returns older version; `floorToBundled` with older/newer/null/equal scraped; `LATEST_KNOWN_FIRMWARE` constant is `2.5`.
